Execution Modes
---------------

n8n supports two primary execution modes that determine how workflows are processed:

| Mode | Description | Process Type | Use Cases |
| --- | --- | --- | --- |
| `regular` | Direct execution in main process | Single process | Development, small deployments |
| `queue` | Distributed execution via Redis queue | Multi-process | Production, high-scale deployments |

The execution mode is configured via the `executions.mode` environment variable and affects how `WorkflowRunner` processes execution requests.

### ScalingService

The `ScalingService` manages the Redis-based job queue and coordinates between main and worker processes:

**Key Methods:**

Recovery and Resilience
-----------------------

### Execution Recovery Service

The `ExecutionRecoveryService` handles recovery of interrupted executions using event logs:

**Execution Recovery Flow**

**Recovery Mechanisms:**

*   **Event Log Analysis**: Uses `toRelevantMessages()` to separate node and workflow events
*   **Task Data Generation**: Creates artificial task data using `ARTIFICIAL_TASK_DATA` for completed nodes
*   **Error Injection**: Marks crashed nodes with `NodeCrashedError` and workflow with `WorkflowCrashedError`
*   **Status Correction**: Updates execution status from 'running' to 'crashed' or preserves 'error' status
*   **Lifecycle Hooks**: Runs `workflowExecuteAfter` hooks to ensure proper cleanup and notifications

### Queue Recovery

The `ScalingService` implements queue recovery to handle dangling executions:

**Queue Recovery Process**

**Recovery Mechanisms:**

*   **Periodic Scanning**: Uses `setTimeout` with configurable interval (default from `executions.queueRecovery.interval`)
*   **Batch Processing**: Processes recovery in batches controlled by `executions.queueRecovery.batchSize`
*   **Status Correction**: Marks dangling executions as 'crashed' via `executionRepository.markAsCrashed()`
*   **Adaptive Timing**: Halves wait time when full batches are found, indicating more dangling executions may exist
*   **Leader-Only Operation**: Only runs on leader instance via `@OnLeaderTakeover` and `@OnLeaderStepdown` decorators
