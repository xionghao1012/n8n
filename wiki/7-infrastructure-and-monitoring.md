Prometheus Metrics System
-------------------------

n8n provides comprehensive monitoring through a Prometheus-compatible metrics endpoint that exposes system performance data, application metrics, and operational insights.

The `PrometheusMetricsService` class serves as the central component for metrics collection and exposure:

**Prometheus Metrics System Architecture**

Sources: [packages/cli/src/metrics/prometheus-metrics.service.ts 21-347](https://github.com/xionghao1012/n8n/blob/master/packages/cli/src/metrics/prometheus-metrics.service.ts#L21-L347)

### Metric Categories and Configuration

The metrics system supports five main categories, each configurable through environment variables:

| Category | Environment Variable | Description |
| --- | --- | --- |
| `default` | `N8N_METRICS_INCLUDE_DEFAULT_METRICS` | Node.js process metrics (CPU, memory, event loop) |
| `routes` | `N8N_METRICS_INCLUDE_API_ENDPOINTS` | HTTP request duration and activity |
| `cache` | `N8N_METRICS_INCLUDE_CACHE_METRICS` | Cache hits, misses, and updates |
| `logs` | `N8N_METRICS_INCLUDE_MESSAGE_EVENT_BUS_METRICS` | Internal event counters |
| `queue` | `N8N_METRICS_INCLUDE_QUEUE_METRICS` | Job queue statistics (scaling mode only) |

### Key Metrics Exposed

#### System Metrics

| Metric Name | Type | Description |
|-------------|------|-------------|
| `process_cpu_user_seconds_total` | Counter | Total user CPU time spent in seconds |
| `process_cpu_system_seconds_total` | Counter | Total system CPU time spent in seconds |
| `process_cpu_seconds_total` | Counter | Total user and system CPU time spent |
| `process_resident_memory_bytes` | Gauge | Resident memory size in bytes |
| `process_heap_bytes` | Gauge | Process heap size in bytes |
| `nodejs_eventloop_lag_seconds` | Gauge | Event loop lag in seconds |
| `nodejs_active_handles` | Gauge | Number of active handles |
| `nodejs_active_requests` | Gauge | Number of active requests |

#### Application Metrics

| Metric Name | Type | Description |
|-------------|------|-------------|
| `n8n_workflow_executions_total` | Counter | Total workflow executions |
| `n8n_workflow_execution_seconds` | Histogram | Workflow execution duration in seconds |
| `n8n_node_executions_total` | Counter | Total node executions |
| `n8n_node_execution_seconds` | Histogram | Node execution duration in seconds |
| `n8n_credentials_usage_total` | Counter | Total credential usage |
| `n8n_api_requests_total` | Counter | Total API requests |
| `n8n_api_request_duration_seconds` | Histogram | API request duration in seconds |

#### Cache Metrics

| Metric Name | Type | Description |
|-------------|------|-------------|
| `n8n_cache_hits_total` | Counter | Total cache hits |
| `n8n_cache_misses_total` | Counter | Total cache misses |
| `n8n_cache_updates_total` | Counter | Total cache updates |
| `n8n_cache_size_bytes` | Gauge | Current cache size in bytes |

#### Queue Metrics (Scaling Mode Only)

| Metric Name | Type | Description |
|-------------|------|-------------|
| `n8n_queue_jobs_total` | Counter | Total jobs processed |
| `n8n_queue_job_duration_seconds` | Histogram | Job processing duration in seconds |
| `n8n_queue_active_workers` | Gauge | Number of active workers |
| `n8n_queue_waiting_jobs` | Gauge | Number of jobs waiting in queue |

Configuration Management Infrastructure
--------------------------------------

The configuration system follows a hierarchical structure:

1. **GlobalConfig**: Base configuration loaded from environment variables
2. **DatabaseConfig**: Database-specific settings
3. **SecurityConfig**: Security-related settings
4. **EndpointsConfig**: API endpoint configurations
5. **WorkflowsConfig**: Workflow execution settings
6. **UserManagementConfig**: User management settings
7. **TemplatesConfig**: Template management settings
8. **PublicApiConfig**: Public API settings
9. **EventBusConfig**: Event bus settings
10. **CacheConfig**: Cache settings
11. **CredentialsConfig**: Credential management settings
12. **InsightsConfig**: Insights and analytics settings

Event Bus and Internal Monitoring
---------------------------------

The event bus provides real-time monitoring of internal system events:

| Event Type | Description |
|-----------|-------------|
| `workflow.started` | Workflow execution started |
| `workflow.completed` | Workflow execution completed |
| `workflow.failed` | Workflow execution failed |
| `node.started` | Node execution started |
| `node.completed` | Node execution completed |
| `node.failed` | Node execution failed |
| `credentials.used` | Credential used |
| `credentials.updated` | Credential updated |
| `credentials.deleted` | Credential deleted |
| `user.loggedIn` | User logged in |
| `user.loggedOut` | User logged out |
| `user.created` | User created |
| `user.updated` | User updated |
| `user.deleted` | User deleted |

Cache Infrastructure
-------------------

n8n supports multiple cache backends:

1. **MemoryCache**: In-memory cache (default)
2. **RedisCache**: Redis-based distributed cache
3. **MemcachedCache**: Memcached-based distributed cache
