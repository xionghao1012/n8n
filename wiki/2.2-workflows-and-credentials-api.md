# Workflows and Credentials API

This document covers the REST API controllers and services that handle CRUD operations, sharing, and permissions for workflows and credentials in n8n. These APIs provide the primary interface for the frontend and external integrations to manage workflow and credential resources.

## API Architecture Overview

The Workflows and Credentials APIs are built using a controller-service architecture with role-based access control and project-scoped permissions.

### Workflows Controller

The `WorkflowsController` handles all workflow-related API operations with comprehensive CRUD functionality and sharing capabilities.

#### Core Workflow Endpoints

| HTTP Method | Endpoint | Purpose | Key Scopes |
| --- | --- | --- | --- |
| `GET` | `/workflows` | List workflows with filtering | `workflow:read` |
| `POST` | `/workflows` | Create new workflow | `workflow:create` |
| `GET` | `/workflows/:workflowId` | Get single workflow | `workflow:read` |
| `PATCH` | `/workflows/:workflowId` | Update workflow | `workflow:update` |
| `DELETE` | `/workflows/:workflowId` | Delete workflow | `workflow:delete` |
| `POST` | `/workflows/:workflowId/run` | Execute workflow manually | `workflow:execute` |

### Credentials Controller

The `CredentialsController` manages credential CRUD operations with encryption, sharing, and scope-based access control.

#### Core Credential Endpoints

| HTTP Method | Endpoint | Purpose | Key Features |
| --- | --- | --- | --- |
| `GET` | `/credentials` | List credentials | Supports `includeScopes`, `includeData` |
| `POST` | `/credentials` | Create credential | Auto-encrypts data |
| `GET` | `/credentials/:credentialId` | Get single credential | Conditional decryption |
| `PATCH` | `/credentials/:credentialId` | Update credential | Preserves `oauthTokenData` |
| `DELETE` | `/credentials/:credentialId` | Delete credential | Permission-checked |
| `POST` | `/credentials/test` | Test credential | Merges encrypted data |

## Enterprise Sharing Features

The enterprise services extend the base functionality with advanced sharing capabilities.

### Transfer Operations

Both workflows and credentials support ownership transfer between projects:

* **Workflow Transfer**: `PUT /workflows/:id/transfer`
* **Credential Transfer**: `PUT /credentials/:id/transfer`

## Role-Based Access Control

The `RoleService` combines multiple scope sources to determine user permissions:

1. **Global Scopes**: From user's global role (`global:owner`, `global:member`, etc.)
2. **Project Scopes**: From user's role in specific projects (`project:editor`, `project:viewer`, etc.)
3. **Resource Scopes**: From sharing relationships (`workflow:editor`, `credential:user`, etc.)
