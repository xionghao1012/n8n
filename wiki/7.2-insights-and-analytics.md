# Insights and Analytics | n8n-io/n8n | DeepWiki

The Insights and Analytics system provides comprehensive workflow execution monitoring and reporting capabilities for n8n. It collects execution data from workflow runs, processes it through time-based aggregation, and serves analytics through REST APIs. The system supports license-based feature access, configurable data retention, and efficient storage through hierarchical data compaction.

## System Architecture

The Insights system follows a multi-stage data pipeline architecture with collection, processing, storage, and serving components.

### Data Collection Pipeline

The collection system captures workflow execution events and buffers them for efficient database writes.

#### Event Filtering

The collection service filters workflow executions based on status and mode:

| Status | Collected | Mode | Collected |
| --- | --- | --- | --- |
| `success` | ✓ | `webhook` | ✓ |
| `error` | ✓ | `trigger` | ✓ |
| `crashed` | ✓ | `cli` | ✓ |
| `waiting` | ✗ | `manual` | ✗ |
| `canceled` | ✗ | `integrated` | ✗ |
| `running` | ✗ | `internal` | ✗ |

#### Collected Metrics

For each qualifying workflow execution, the system collects:

* **Status Event**: Success or failure count (value: 1)
* **Runtime Event**: Execution duration in milliseconds
* **Time Saved Event**: User-configured time saved value (for successful runs only)

### Data Compaction System

The compaction service aggregates raw data into time-based periods to optimize storage and query performance.

#### Compaction Algorithm

The compaction process uses batch processing with database transactions:

1. **Batch Selection**: Select oldest records up to `compactionBatchSize`
2. **Temporary Table**: Create `rows_to_compact` temporary table
3. **Aggregation**: Group by `metaId`, `type`, and time period
4. **Upsert**: Insert new aggregates or update existing ones
5. **Cleanup**: Delete processed raw records

### Database Schema

The system uses three main entities to store insights data:

#### Type System

Both raw and period entities use integer encoding for type and period unit:

| Type | Number | Description |
| --- | --- | --- |
| `success` | 0 | Successful execution |
| `failure` | 1 | Failed execution |
| `runtime_ms` | 2 | Runtime in milliseconds |
| `time_saved_min` | 3 | Time saved in minutes |

| Period Unit | Number | Description |
| --- | --- | --- |
| `hour` | 0 | Hourly aggregation |
| `day` | 1 | Daily aggregation |
| `week` | 2 | Weekly aggregation |

### REST API Endpoints

The controller provides three main endpoints for querying insights data:

#### API Response Schemas

The system returns structured data with computed metrics:

**Summary Response** (`InsightsSummary`):

* `total`: Total executions with deviation from previous period
* `failed`: Failed executions with deviation
* `failureRate`: Calculated failure rate (0-1) with deviation
* `averageRunTime`: Average runtime in milliseconds with deviation
* `timeSaved`: Total time saved in minutes with deviation

**Workflow Response** (`InsightsByWorkflow`):

* Paginated list of workflows with aggregated metrics
* Supports sorting by various fields (`total`, `failed`, `runTime`, etc.)
* Includes workflow and project metadata

**Time Response** (`InsightsByTime`):

* Time-series data grouped by specified granularity
* Returns date-indexed data points with computed metrics

### License Integration

The system integrates with n8n's licensing system to control feature access and data retention:

#### Date Range Licensing

The system provides different date ranges based on license capabilities:

| Range | Days | Hourly License Required | Granularity |
| --- | --- | --- | --- |
| `day` | 1 | Yes | `hour` |
| `week` | 7 | No | `day` |
| `2weeks` | 14 | No | `day` |
| `month` | 30 | No | `day` |
| `quarter` | 90 | No | `week` |
| `6months` | 180 | No | `week` |
| `year` | 365 | No | `week` |

### Configuration System

The insights system is highly configurable through environment variables:

| Setting | Default | Description |
| --- | --- | --- |
| `N8N_INSIGHTS_COMPACTION_INTERVAL_MINUTES` | 60 | Compaction frequency |
| `N8N_INSIGHTS_COMPACTION_BATCH_SIZE` | 500 | Records per batch |
| `N8N_INSIGHTS_FLUSH_BATCH_SIZE` | 1000 | Buffer size before flush |
| `N8N_INSIGHTS_FLUSH_INTERVAL_SECONDS` | 30 | Flush frequency |
| `N8N_INSIGHTS_MAX_AGE_DAYS` | -1 | Data retention limit |
| `N8N_INSIGHTS_PRUNE_CHECK_INTERVAL_HOURS` | 24 | Pruning frequency |

### Module Initialization

The insights module initializes conditionally based on instance type and starts the necessary timers:

The insights system only activates on `main` and `webhook` instance types since only these receive workflow execution completion events. Worker instances skip insights initialization entirely.
