# 洞察与分析 | n8n-io/n8n | DeepWiki

洞察与分析系统为n8n提供全面的工作流执行监控和报告功能。它从工作流运行中收集执行数据，通过基于时间的聚合进行处理，并通过REST API提供分析数据。该系统支持基于许可证的功能访问、可配置的数据保留以及通过分层数据压缩实现的高效存储。

## 系统架构

洞察系统采用多阶段数据管道架构，包含收集、处理、存储和服务组件。

### 数据收集管道

收集系统捕获工作流执行事件并对其进行缓冲，以实现高效的数据库写入。

#### 事件过滤

收集服务根据状态和模式过滤工作流执行：

| 状态 | 是否收集 | 模式 | 是否收集 |
| --- | --- | --- | --- |
| `success` | ✓ | `webhook` | ✓ |
| `error` | ✓ | `trigger` | ✓ |
| `crashed` | ✓ | `cli` | ✓ |
| `waiting` | ✗ | `manual` | ✗ |
| `canceled` | ✗ | `integrated` | ✗ |
| `running` | ✗ | `internal` | ✗ |

#### 收集的指标

对于每个符合条件的工作流执行，系统收集：

* **状态事件**：成功或失败计数（值：1）
* **运行时事件**：执行持续时间（毫秒）
* **节省时间事件**：用户配置的节省时间值（仅适用于成功运行）

### 数据压缩系统

压缩服务将原始数据聚合到基于时间的周期中，以优化存储和查询性能。

#### 压缩算法

压缩过程使用数据库事务进行批处理：

1. **批选择**：选择最早的记录，最多达`compactionBatchSize`
2. **临时表**：创建`rows_to_compact`临时表
3. **聚合**：按`metaId`、`type`和时间段分组
4. **更新插入**：插入新聚合或更新现有聚合
5. **清理**：删除已处理的原始记录

### 数据库模式

系统使用三个主要实体存储洞察数据：

#### 类型系统

原始实体和周期实体都使用整数编码表示类型和周期单位：

| 类型 | 数字 | 描述 |
| --- | --- | --- |
| `success` | 0 | 成功执行 |
| `failure` | 1 | 失败执行 |
| `runtime_ms` | 2 | 运行时间（毫秒） |
| `time_saved_min` | 3 | 节省时间（分钟） |

| 周期单位 | 数字 | 描述 |
| --- | --- | --- |
| `hour` | 0 | 每小时聚合 |
| `day` | 1 | 每天聚合 |
| `week` | 2 | 每周聚合 |

### REST API端点

控制器提供三个主要端点用于查询洞察数据：

#### API响应模式

系统返回包含计算指标的结构化数据：

**摘要响应**（`InsightsSummary`）：

* `total`：总执行次数及与上一周期的偏差
* `failed`：失败执行次数及偏差
* `failureRate`：计算的失败率（0-1）及偏差
* `averageRunTime`：平均运行时间（毫秒）及偏差
* `timeSaved`：总节省时间（分钟）及偏差

**工作流响应**（`InsightsByWorkflow`）：

* 带聚合指标的工作流分页列表
* 支持按各种字段排序（`total`、`failed`、`runTime`等）
* 包含工作流和项目元数据

**时间响应**（`InsightsByTime`）：

* 按指定粒度分组的时间序列数据
* 返回带计算指标的日期索引数据点

### 许可证集成

系统与n8n的许可系统集成，以控制功能访问和数据保留：

#### 日期范围许可

系统根据许可证功能提供不同的日期范围：

| 范围 | 天数 | 是否需要Hourly许可证 | 粒度 |
| --- | --- | --- | --- |
| `day` | 1 | 是 | `hour` |
| `week` | 7 | 否 | `day` |
| `2weeks` | 14 | 否 | `day` |
| `month` | 30 | 否 | `day` |
| `quarter` | 90 | 否 | `week` |
| `6months` | 180 | 否 | `week` |
| `year` | 365 | 否 | `week` |

### 配置系统

洞察系统可通过环境变量高度配置：

| 设置 | 默认值 | 描述 |
| --- | --- | --- |
| `N8N_INSIGHTS_COMPACTION_INTERVAL_MINUTES` | 60 | 压缩频率 |
| `N8N_INSIGHTS_COMPACTION_BATCH_SIZE` | 500 | 每批记录数 |
| `N8N_INSIGHTS_FLUSH_BATCH_SIZE` | 1000 | 刷新前的缓冲区大小 |
| `N8N_INSIGHTS_FLUSH_INTERVAL_SECONDS` | 30 | 刷新频率 |
| `N8N_INSIGHTS_MAX_AGE_DAYS` | -1 | 数据保留限制 |
| `N8N_INSIGHTS_PRUNE_CHECK_INTERVAL_HOURS` | 24 | 清理频率 |

### 模块初始化

洞察模块根据实例类型有条件地初始化，并启动必要的计时器：

洞察系统仅在`main`和`webhook`实例类型上激活，因为只有这些实例接收工作流执行完成事件。工作器实例完全跳过洞察初始化。
