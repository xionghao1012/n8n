# Parameter Inputs and Resource Locator | n8n-io/n8n | DeepWiki

This document covers the parameter input system in n8n's user interface, with specific focus on the Resource Locator Component (RLC). Parameter inputs are the form controls that allow users to configure node parameters in the Node Details View (NDV). The Resource Locator is a specialized parameter input type that enables dynamic resource selection from external services with real-time validation and search capabilities.

For general information about the Node Details View container, see [Node Details View (NDV)](https://deepwiki.com/n8n-io/n8n/4.1-node-details-view-(ndv)). For broader frontend architecture topics, see [Frontend Architecture and State Management](https://deepwiki.com/n8n-io/n8n/4.3-frontend-architecture-and-state-management).

## Parameter Input System Overview

The parameter input system provides various input components for configuring node parameters, including text fields, dropdowns, toggles, and specialized components like the Resource Locator. These inputs are rendered dynamically based on node parameter definitions and support features like expression editing, validation, and real-time updates.

## Resource Locator Component Architecture

The Resource Locator Component (RLC) is a sophisticated parameter input that enables users to select resources from external services dynamically. It provides multiple selection modes, real-time validation, and integration with the credential system.

## Resource Locator Error Handling

The Resource Locator implements comprehensive error handling to guide users through credential setup and validation issues. The system provides contextual error messages and actionable next steps.

| Error Condition | Message | User Action Available |
| --- | --- | --- |
| No Credentials Set | "Add your credential" | Click to open CredentialsModal |
| Invalid Credentials | "Check your credential" | Review and update credentials |
| Search Filter Required | Varies by node | Provide required search parameters |
| Network/API Error | Service-specific message | Retry or check connection |

## Integration with Node System

Resource Locators integrate seamlessly with the broader node system, handling parameter dependencies and maintaining state consistency across related fields. The system supports complex scenarios where one resource selection affects the available options for dependent fields.

### Key Integration Points

* **Parameter Dependencies**: Resource Locators automatically reset dependent fields when primary selections change
* **Credential Integration**: Direct integration with the credential management system for authentication
* **Error Recovery**: Robust error handling that allows continued operation even when some parameters have validation errors
* **Real-time Validation**: Immediate feedback on credential status and resource availability

### Example Usage Patterns

The Google Sheets node demonstrates typical Resource Locator usage with two interdependent RLC fields:

1. `documentId` - Primary resource locator for selecting Google Sheets documents
2. `sheetName` - Dependent resource locator that resets when document selection changes

This pattern ensures data consistency and provides an intuitive user experience where changing the document automatically clears the sheet selection, prompting the user to select an appropriate sheet from the new document.
